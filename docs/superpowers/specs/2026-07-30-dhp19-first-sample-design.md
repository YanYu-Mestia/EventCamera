# DHP19 第一组数据验证设计

日期：2026-07-30  
状态：已确认

## 目标

在不改动原始 DHP19 数据的前提下，为 `S1/session1/mov1` 建立一个可重复、可测试的官方兼容处理闭环：正确读取四相机 AEDAT2 事件流，将前 20 个恒定事件数量帧与 Vicon 三维姿态对齐，生成 HDF5 数据和四相机关节点叠加图。

## 范围

输入固定为：

- 事件：`D:\DHP19\DVS_movies\S1\session1\mov1.aedat`
- 标签：`D:\DHP19\Vicon_data\S1_1_1.mat`
- 标定：`D:\DHP19\P_matrices\P1.npy` 至 `P4.npy`

输出固定为：

- 目录：`D:\DHP19_preprocessed\verification\S1_session1_mov1_20frames`
- 四相机事件文件：`S1_session1_mov1_7500events_first20.h5`，数据集 `/DVS`；Python/h5py 读取形状为 `(20, 260, 346, 4)`，对应官方 MATLAB 逻辑维度 `(4, 346, 260, 20)`
- 三维姿态标签文件：`S1_session1_mov1_7500events_first20_label.h5`，数据集 `/XYZ`；Python/h5py 读取形状为 `(20, 3, 13)`，对应官方 MATLAB 逻辑维度 `(13, 3, 20)`
- 前 20 帧处理摘要，包括同步时间、原始/保留事件数、帧时间范围和标签索引范围
- 至少一组四相机关节点叠加图，用于人工确认空间投影和时间同步

本阶段不处理其余记录，不训练模型，不修改原始 `.aedat`、`.mat` 或已有预处理数据，也不把生成数据提交到 Git。

## 实现方案

### 运行环境

在 WSL Ubuntu 的 `/home/mestia/miniconda3` 下创建独立 Conda 环境 `eventpose-dhp19`，使用 Python 3.12。环境只包含本阶段需要的 NumPy、SciPy、h5py、Matplotlib、Numba 和 pytest；Numba 用于编译官方逐事件背景活动过滤循环，避免数百万事件在纯 Python 中逐个处理。PyTorch、MMPose 与 GPU 训练依赖留到数据闭环验证之后。

项目保存一份可重复创建该环境的环境定义文件。现有 WSL base、Windows `event_pose` 及其他 Conda 环境保持不变。

### 官方数据补充

本地缺少 `P_matrices`。处理前从 ETH DHP19 官方共享目录下载该文件夹并校验其中存在 `P1.npy`、`P2.npy`、`P3.npy`、`P4.npy`、`camera_positions.npy` 和两份标定点 CSV。下载只补充缺失标定文件，不下载 145.5 GB 的完整数据集。

### AEDAT2 解析

解析行为以 SensorsINI/DHP19 官方仓库的 `ImportAedatDataVersion1or2.m` 和 `Generate_DHP19.m` 为准：

- 跳过 `#!AER-DAT2.0` 文本头；
- 以大端序读取 32 位地址和 32 位微秒时间戳；
- 区分普通极性事件与同步特殊事件；
- 解码相机编号、横纵坐标和极性；
- 保留四台相机，原始单相机分辨率为 `346 x 260`；
- 根据官方规则使用特殊事件和 Vicon 样本长度确定同步起止时间；
- 应用官方热像素、背景活动和红外区域过滤逻辑；
- 每个输出帧累计过滤后的 30,000 个事件，即平均每台相机 7,500 个事件。

现有 `scripts/data/dhp19_dataset.py` 保持原样并继续视为原型，正式解析逻辑放入新的独立模块，避免未经验证的行为影响其他代码。

### 标签对齐

从 `S1_1_1.mat` 的 `XYZPOS` 读取 13 个关节点。Vicon 采样频率为 100 Hz，事件时间戳单位为微秒。每个事件帧结束时计算对应 Vicon 索引，并对该帧时间覆盖范围内的关节点坐标使用忽略 NaN 的均值，保持官方关节点顺序：

1. head
2. shoulderR
3. shoulderL
4. elbowR
5. elbowL
6. hipR
7. hipL
8. handR
9. handL
10. kneeR
11. kneeL
12. footR
13. footL

`S1_1_1.mat` 已确认所有值有限；实现仍需显式检测 NaN，以便后续扩展到其他记录。

### 可视化

使用 `P1.npy` 至 `P4.npy` 将每帧的三维关节点投影到对应事件相机。沿用官方 `heatmap_generation_example.ipynb` 的通道映射：事件通道 0、1、2、3 分别使用 `P4`、`P1`、`P3`、`P2`。叠加图必须标出关节点和骨架连接，并保留相机编号、帧编号和时间范围。投影落在画面外的点不绘制，但需在摘要中计数。

## 错误处理

以下情况必须中止并给出明确错误，不生成看似成功的半成品：

- 输入事件、标签或任一投影矩阵缺失；
- AEDAT2 头或记录长度无效；
- 相机编号或坐标超出官方范围且比例异常；
- 找不到可用的同步起止时间；
- Vicon 关节点字段、形状或样本范围不符合约定；
- 不足以生成 20 个完整事件帧；
- HDF5 输出形状或数值检查失败。

输出先写入临时文件，全部验证通过后再替换目标文件，避免中断后留下被误认为完整结果的文件。

本阶段完成必须同时满足：

- `eventpose-dhp19` 可由项目定义重复创建并通过环境检查；
- 自动化测试全部通过；
- 真实处理命令退出码为 0；
- Python/h5py 读取 `/DVS` 的形状为 `(20, 260, 346, 4)` 且每帧包含有效事件；

- 四相机叠加图可打开、非空且关节点投影数据有记录；
